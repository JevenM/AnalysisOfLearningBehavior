# 可验证成果 · 运行说明

> 对应《2026 年实践项目指南》4.4「可验证成果」与表 4「可验证成果演示评分标准」。
> 交付物：`run_all.py`（一键复现入口）+ `up_*.py` 统一管线八阶段（六源主线）
> + `multimodal.py`（多形态测评）+ `profile_modeling.py`（内容级画像）+ 三个单文件离线看板。
> **全文无仿真样本**：全部分析建立在六类真实公开数据集的统一合并总表之上（66,644 名学习者），
> 不单独拆分任何一个数据集。

## 一、环境与依赖

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11（实测 Windows 11）；Linux/macOS 亦可 |
| Python | 3.10 及以上（开发验证 3.14） |
| 依赖 | 见 `03_源代码/requirements.txt`：numpy / pandas / scipy / scikit-learn / matplotlib / python-docx |
| 浏览器 | 任意现代浏览器（Chrome / Edge / Firefox），看板无需联网 |
| GPU（可选） | `--device gpu` 时自动探测 RAPIDS cuML（Linux/WSL）或 PyTorch CUDA（Windows 可用），CPU 自动回退 |

安装依赖（只需一次，在交付包根目录执行）：

```bash
pip install -r 03_源代码/requirements.txt
```

## 二、运行方式

### 方式 0｜一键运行（`run_all.py`，推荐）

把整条分析链封装为一个命令。默认使用随包派生数据，离线可复现，无需重新下载数据或记忆脚本顺序：

```bash
cd ..                                    # 回到交付包根目录
python 03_源代码/run_all.py --check      # 第一步：只读体检（依赖 / 数据 / 结果文件 / 看板）
python 03_源代码/run_all.py              # 第二步：一键全链路（结果→看板）
python 03_源代码/run_all.py --device gpu # 变体：统一管线聚类启用 GPU 加速
```

参数：

| 参数 | 作用 |
| --- | --- |
| `--check` | 只体检、不改文件；逐项报告依赖、派生数据、结果 JSON/CSV、插图、看板是否齐全 |
| `--device auto\|cpu\|gpu` | 计算设备选择，经环境变量 `WB_DEVICE` 贯通全部子进程（加速 KMeans/轮廓系数/最近质心分配） |
| `--skip-report` | 预留参数，跳过可选的下游报告步骤 |

执行顺序：`multimodal（四形态测评）→ profile_modeling（内容级画像）→
统一管线 up_1..up_8（主线）→ 三个看板`。每步独立子进程、打印耗时、失败即停；
重复运行会幂等覆盖，不会产生重复结果。

### 方式 0.5｜建模控制台（可交互改参 / 换数据重跑，答辩现场用）

对应指南 4.4（1）（2）：可交互界面 + 现场更换输入数据或参数后重新运行、解释结果变化。

```bash
python 03_源代码/model_console.py            # 启动本地控制台（标准库实现，无额外依赖）
python 03_源代码/model_console.py --port 8001 --no-browser   # 变体
```

| 控制台能力 | 说明 |
| --- | --- |
| 改参数 | 聚类数 K（0=自动）/ 计算设备 / Apriori 支持度与置信度 / SD 仿真周数 / 多形态预算比例 |
| 换数据 | 上传自定义学习者总表（与 up_unified.csv 同 schema：student_id/source/total_clicks/active_days/final_grade/success/completion_rate），一键恢复默认 |
| 重跑 | 沙箱模式 → `04_运行结果_沙箱/`（不动正式结果，约 1–3 分钟）；正式模式 → `04_运行结果/` 并自动刷新三个看板 |
| 看变化 | 每次运行自动与上一次快照对比：预测指标 / 四类画像 / 干预队列 / 优化建议逐行高亮（▲▼） |
| 互链 | 页面托管三个看板与 up_report.md（`/dash/…`、`/files/…`），看板头部也有控制台入口 |

答辩话术提示（控制台底部也内置）：K 调大 → 画像更细、轮廓系数通常下降；Apriori 支持度调低 →
长尾规则增多；预算比例调低 → 规划最优增益下降但单位预算效率上升；SD 周数调大 →
资源供给复利效应更显著；换数据 → 全部指标随新样本重算，可与默认六源结果对比解释差异来源。

### 方式 0.6｜现场测试：更换输入数据完整流程（对应课程要求 2）

#### 1. 测试文件在哪、用哪个

**`02_数据与数据集/测试上传数据/test_upload_harvardx_holdout.csv`**（8,000 名学习者 × 28 列）。
这是**真正未参与建模的留出数据**：HarvardX-MITx Person Course 数据集共 323,419 名真实注册用户，
正式六源合并总表只随机抽用了 5 万人（`up_adapters.py` 的 5 万上限），本文件取自其余
226,961 名未入模且真实行为事件数>0 的留出用户（固定随机种子，认证率 5.1%，
与正式总表的学习者**零重叠**）。生成脚本与再生成命令：

```bash
python 03_源代码/build_test_upload.py          # 默认 8,000 人；--n 5000 可调
```

> 若教师使用自备数据，无需该文件——上传文件只需满足下表格式即可。

#### 2. 上传数据格式要求

与 `04_运行结果/up_unified.csv` 同 schema 的 CSV（UTF-8 编码，含表头，BOM 可选）：

| 级别 | 列名 | 要求 |
| --- | --- | --- |
| **必需**（缺一拒收并提示） | `student_id` | 学习者唯一编号（不重复） |
| | `source` | 数据来源标记（任意字符串，如 `test:harvardx_holdout`） |
| | `total_clicks`、`active_days` | 行为量：非负数值 |
| | `final_grade` | 成绩 0–100 数值（可为空，空值行不参与等级分档） |
| | `success`、`completion_rate` | 结果标签：`success` 取 0/1（或 pass/fail、certified/none 等可映射二值）；`completion_rate` 取 0–1 |
| 推荐（画像/分层更完整） | `gender`、`age_band`、`education` | 人口属性，缺失不阻断 |
| | `video_clicks`、`forum_posts`、`resource_clicks`、`quiz_attempts`、`avg_quiz_score` 等 | 行为细项，允许缺失 |
| 规模建议 | 行数 500–20,000 | 太小聚类不稳，太大运行变慢（8,000 约 5–8 分钟） |

- 允许缺失：行为特征列缺失时，管线自动选取缺失率≤40% 的列聚类并中位数填充，标签列缺失行剔除；
- **不需要**事件流明细列：控制台自动沿用默认事件流（Apriori/GM(1,1) 演示口径），页面上有说明；
- 上传校验：服务端检查必需列，缺列直接报错并提示缺哪些；正式总表替换前自动备份为
  `up_unified.default.csv`，可一键恢复。

#### 3. 操作流程（答辩现场约 6 步，全程 5–10 分钟）

1. **启动控制台**：`python 03_源代码/model_console.py`（自动打开浏览器）；
2. **上传**：页面"② 输入数据"→ 目标选"写入沙箱"→ 选择测试文件 → 提示上传成功（8,000 行）；
3. **选范围**："③ 运行"→ 选"沙箱试验（用已上传数据，从聚类起跑）"→ 点"按新参数运行"；
4. **看日志**：聚类 → 挖掘 → 相关 → 预测 → 评价 → 决策 → 报告七阶段实时滚动，任一阶段失败即停并显示退出码；
5. **看对比**：结束后"⑤ 结果摘要与变化对比"自动刷新——与本次运行前快照逐行对比，变化行高亮（▲▼），
   包括 K、轮廓系数、认证判断准确率、早期预警 AUC、四类画像人数、干预队列人数、
   SD 最优策略与优化建议条数；
6. **收尾**：点"恢复默认数据 / 清空沙箱"还原（沙箱目录整体删除，正式结果全程未被触碰）。

若需把新数据结果固化为正式结果：上传时目标选"替换正式总表（自动备份默认表）"，
运行"正式 · 统一管线 + 三看板"，三个看板即按新数据刷新；`python 03_源代码/run_all.py --check`
可随时验证结果链自洽。

#### 4. 预期变化与解释要点（留出文件实跑结论）

- **画像/队列结构显著变化**：留出文件为单来源（edX 慕课）、认证率仅 5.1%、平均点击 513 次，
  远低于六源混合总表——"低投入高绩效型/风险流失型"占比与队列分配会大幅移动，
  可解释为"输入数据分布决定画像结构"；
- **成绩等级分类可能自动降级**：单来源数据 `grade_band` 可能仅一类（管线打印警告并跳过等级分类，
  保留认证二分类与回归口径）——这本身是答辩亮点：程序对任意输入优雅降级而非崩溃；
- **预测指标变化**：cert_acc / 早期 AUC 随新样本重算（留出数据约 0.90+，六源为 0.94+），
  说明模型指标依赖数据覆盖面，不是固定数值；
- **不变项**：方法链（K 自动选优、AHP 一致性检验、0-1 规划约束）与流程逻辑不变——
  验证的是"方法可迁移"，变化的只是数据驱动的数值结果。

## 五、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `--check` 提示缺依赖 | `python -m pip install -r 03_源代码/requirements.txt` |
| 报告 docx 生成失败（PermissionError） | Word/WPS 正占用文件；关闭后重跑 `python 01_研究报告/build_final_report.py` |

| 重跑后看板未更新 | 看板是静态注入产物，需重跑对应 `build_*.py`（一键链已包含） |
