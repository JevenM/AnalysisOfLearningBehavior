# 可验证成果 · 运行说明

> 对应《2026 年实践项目指南》4.4「可验证成果」与表 4「可验证成果演示评分标准」。
> 交付物：`app.py`（交互验证平台）+ `analysis.py`（主线模型流水线）+ `build_real_learners.py`（OULAD 真实主表派生）
> + `forecast.py` / `fuzzy_eval.py`（预测与模糊评价）+ `multimodal.py`（多形态真实数据测评）。
> **全文无仿真样本**：两条并重的真实证据链——课程级为 OULAD 真实数据（结业结果标签），
> 国内内容级为六源真实公开数据（短视频 / 微课 / MOOC / 课堂对照，过程与持续性标签）。两条链分层建模、不混算。

## 一、环境与依赖

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11（实测 Windows 11）；Linux/macOS 亦可 |
| Python | 3.10 及以上（代码用类型联合写法；开发验证 3.11/3.14） |
| 依赖 | 见 `03_源代码/requirements.txt`：numpy / pandas / scipy / scikit-learn / matplotlib / python-docx |
| 浏览器 | 任意现代浏览器（Chrome / Edge / Firefox），看板无需联网 |

安装依赖（只需一次，在交付包根目录执行）：

```bash
pip install -r 03_源代码/requirements.txt
```

## 二、运行方式

### 方式 0｜一键运行（`run_all.py`，推荐）

参照借鉴仓库 `main.py` 的单入口模式，把整条分析链封装为一个命令。默认使用随包派生数据，
完全离线可复现，无需重新下载数据或记忆脚本顺序：

```bash
cd ..                                    # 回到交付包根目录
python 03_源代码/run_all.py --check      # 第一步：只读体检（依赖 / 数据 / JSON / 看板 / 报告）
python 03_源代码/run_all.py              # 第二步：一键全链路（结果→图表→看板→报告）
python 03_源代码/run_all.py --web        # 或：全链路后直接启动交互平台
```

参数：

| 参数 | 作用 |
| --- | --- |
| `--check` | 只体检、不改文件；逐项报告依赖、派生数据、结果 JSON、插图、看板、报告是否齐全 |
| `--web` | 全链路完成后启动 Web 平台（`http://127.0.0.1:8765`），配合 `--port` 改端口 |
| `--skip-report` | 跳过 docx 重建（Word/WPS 正占用报告文件时使用） |
| `--from-raw --oulad-dir <目录>` | 额外从 OULAD 原始表（约 443 MB，不随包）重新派生主表与预测面板；默认跳过 |

执行顺序（自动保证依赖正确）：`multimodal → app.py --batch（挂载多形态结果）→ forecast →
fuzzy → profile → demo_runs → figures → 三个看板 → 报告`。每步独立子进程、打印耗时、失败即停；
重复运行会幂等覆盖，不会产生重复结果。

#### 重跑操作详解：上传什么文件、参数怎么设

**第一步，选数据源（二选一）**

| 数据源 | 说明 | 何时用 |
|---|---|---|
| 内置 OULAD 真实数据 | 随包的 `real_learners.csv`，20,105 条 / 18,634 人 | 默认。验证建模流程、改参对比 |
| 现场上传的真实 CSV | 自己按模板准备的*真实*学习者行为数据 | 验证"能读入外部数据、非写死" |

上传文件的具体要求：

- 格式 **UTF-8（可带 BOM）CSV，首行表头**，字段名与 `real_learners.csv` 完全一致；
- 必需 20 个字段（清单见「五、输入数据字段口径」），其中 `certificate` 只能是 0/1、
  `course_id` 用字符串、`study_hours` 为点击折算的等效时长；
- **点验证控制台里的「下载模板前 5 行」** 可直接拿到正确表头的示例，照着补数据即可；
  没有真实数据时可先用内置源，不必强行上传合成数据（本项目不接收仿真样本）。

**第二步，设置参数（都有默认值，不改就是报告基准）**

| 参数 | 默认值 | 取值范围 | 作用与影响 |
|---|---|---|---|
| 画像数 k | 4 | 2–8 | K-means 把学习者分成几类；改了看分类粒度与轮廓系数变化 |
| 干预预算比例 | 45% | 20%–100% | 可用预算占总成本的比例；影响 0-1 规划选出的干预组合与新增达标人数 |
| 测试集比例 | 25% | 20%–35% | 预测模型留出多少数据做测试；越大评估越稳但训练越少 |
| AHP 主观权重 α | 0.50 | 0–1 | 主观(AHP)与客观(熵权)的组合比例；1=全主观，0=全客观 |
| 评价权重模式 | 组合 | 组合 / 自定义 | 选"自定义"后可手动调 6 个指标权重 |
| 随机种子 | 20260101 | 整数 | 只固定 K-means/交叉验证的随机性，保证可复现；**不是仿真参数** |
| 运行模式 | 完整 | 完整 / 快速 | 完整≈90s（含 k 扫描、三模型 5 折 CV、8 档预算扫描，与报告一致）；快速≈10s（仅 Logistic 主模型，适合连续改参） |

**第三步，点「运行验证 / 改参重跑」**，等待进度提示，完成后看两处变化：
左侧日志区给出本次参数与耗时，主区图表与指标卡刷新，并列出"与报告基准的差异 Δ"。
若要还原，点「恢复报告基准结果」。

> 注意：离线双击 HTML 打开时是"离线预览模式"，只能拖动权重/预算滑块做**前端即时演示**；
> 真正读入 CSV、重新建模必须通过 `app.py` 启动的**在线验证模式**（浏览器访问 `http://127.0.0.1:8765`）。

服务启动后还可访问 `http://127.0.0.1:8765/persona` 打开**学习者画像分析看板**：顶部在慕课 / 微课 /
短视频 / 课堂对照间切换，点击画像群联动雷达与散点，切换 X/Y 轴探索个体行为分布，
并查看各形态的达标驱动系数与跨形态对比。该看板也可直接双击 `05_图表与看板/persona_dashboard.html`
离线打开（无需后端）。

访问 `http://127.0.0.1:8765/profile` 打开**六维画像看板**：顶部在地区差异 / 专业背景 /
学习习惯 / 兴趣爱好 / 短视频用户属性（国内：城市等级·性别·年龄·时段）/ 天池倍速标签
（国内：倍速·设备·OS·网络·预习）间切换，含可排序分组表、联动条形图与卡方 / Kruskal–Wallis /
Mann–Whitney 差异检验，底部显式标注各维度的代理口径与伦理边界。其中地域涵盖英国 OULAD 13 大区
与中国短视频 365 城市双来源，分层呈现不合并。该看板同样可双击 `05_图表与看板/profile_dashboard.html`
离线打开。两个画像看板与主看板之间互有跳转入口。

完整模式约 90 秒（真实数据 2 万条，含 k 扫描、三模型 5 折 CV、8 档预算扫描）；
快速模式约 10 秒（仅 Logistic 主模型），适合现场连续改参。

## 四、现场改参重跑演示建议（答辩 5 分钟）

| 步骤 | 操作 | 预期现象与解释口径 |
| --- | --- | --- |
| 1 | 默认参数运行一次 | k=4、轮廓 0.3684、无泄漏 AUC≈0.85、最优新增通过约 1,126 人，与报告一致 |
| 2 | 预算比例 45%→20%，快速模式重跑 | 预算降至 18.5 万元，最优增益降至约 538 人，说明预算是硬约束 |
| 3 | k 从 4 改为 3 或 6，重跑 | 轮廓系数变化、画像合并或细分，决策按新群体规模重解，说明粒度传导 |
| 4 | α 从 0.5 改为 0.8 | 组合权重向 AHP 倾斜，评价排序稳健，说明结论不过度依赖赋权偏好 |
| 5 | 上传字段相同的真实 CSV 子集 | 样本量、群体规模、预算与最优增益同步变化，证明读入外部输入而非写死 |
| 6 | 另开终端执行 `python multimodal.py` | 打印分形态 AUC、形态效应 ΔAUC=0.0998、6 组迁移与跨形态决策；看板第 7 板块同步 |

> 质询呼应：数据从哪来（OULAD 主线 + 六源多形态，均真实、分章不混算）、
> 结果如何验证（通过率梯度 + 无泄漏 5 折 CV + 一致性检验 + 三方案对照 + 真实数据 bootstrap/标签口径对照 + 现场重跑）。

## 五、输入数据字段口径

上传 CSV 需为 UTF-8（可带 BOM）、首行表头，必需 20 个字段（与 `real_learners.csv` 一致）：

```
record_id, learner_id, course_id, course_name, discipline, region,
education, gender, age, visit_count, active_days, study_hours,
avg_session_min, forum_posts, first_active_lag, video_rate,
assign_rate, quiz_avg, final_grade, certificate
```

- `course_num`（选课门数）由 `load_clean()` 依据 `learner_id × course_id` 自动派生，**不需要提供**；
- `early_w2_* / early_w4_*`（前期行为）与 `prev_attempts`（既往重修）为无泄漏预测字段，缺失时自动补 0；
- 允许存在缺失、重复、时长异常、课程号大小写不一致——清洗流程会处理并在日志中报告；
- 可在界面点「下载模板前 5 行」获取示例，或复制 `02_数据与数据集/real_learners.csv` 的表头。

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 端口被占用 | `python app.py --port 9001` 换端口 |
| 上传后提示缺字段 | 按上表核对列名；`certificate` 必须为 0/1，`course_id` 需为字符串 |
| 页面显示「离线预览模式」 | 直接双击 HTML 所致；运行 `python app.py` 并从 `http://127.0.0.1:8765` 访问即可 |
| 完整模式耗时较长 | 属正常（约 90 s，真实数据 2 万条）；连续改参请切「快速预览」 |
| 中文图表乱码 | 确认系统已安装 SimHei 或 Microsoft YaHei 字体 |
| 结果与报告略有出入 | 检查是否改过参数；点「恢复报告基准结果」或重新执行 `--batch` |
